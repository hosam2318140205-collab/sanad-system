# نظام كاشير POS لمحلات الملابس

نظام نقاط بيع ومخزون متكامل لمحلات الملابس في السعودية — **Next.js 16 + TypeScript + Supabase (PostgreSQL)**، بواجهة عربية RTL تعمل على الجوال والكمبيوتر.

## المزايا

| الوحدة | التفاصيل |
|---|---|
| **نقطة البيع** | بحث فوري ومسح باركود (قارئ USB/Bluetooth)، اختيار المقاس واللون، خصم على السطر أو الفاتورة (مبلغ/نسبة)، تعليق واستئناف الفواتير، اختصارات لوحة المفاتيح (F2 بحث، F4 عميل، F8 تعليق، F9 دفع) |
| **الدفع** | نقدي / شبكة (مدى-فيزا) / تحويل، تقسيم الدفع، حساب الباقي، أزرار مبالغ سريعة |
| **الضريبة** | VAT 15% (قابلة للتعديل)، أسعار شاملة أو غير شاملة الضريبة، الحساب يتم في قاعدة البيانات وليس في المتصفح |
| **الفاتورة** | فاتورة ضريبية مبسطة حرارية 80mm / 58mm مع **رمز QR متوافق مع هيئة الزكاة (ZATCA — المرحلة الأولى)** |
| **المنتجات** | صور، تصنيفات، ماركات، مولّد مقاسات × ألوان، **كل Variant بمخزون وباركود وسعر وتكلفة مستقلة**، توليد باركود EAN-13 داخلي، طباعة ملصقات 50×30mm |
| **المرتجعات والاستبدال** | إرجاع جزئي أو كلي، إعادة للمخزون أو تسجيل كتالف، استرداد نقدي/شبكة/تحويل، أو **رصيد استبدال** يُستخدم في فاتورة جديدة مرة واحدة فقط، إشعار دائن مطبوع |
| **المخزون** | أرصدة لحظية، تنبيهات النقص، تسويات بسبب إلزامي، سجل حركات كامل لكل قطعة، قيمة المخزون بالتكلفة والبيع |
| **الجرد** | جرد كامل أو حسب التصنيف، العدّ بمسح الباركود (كل مسحة = قطعة)، جرد أعمى للكاشير، عرض الفروقات، اعتماد يضبط الكميات |
| **المشتريات والموردين** | أوامر شراء (مسودة/مطلوب/مستلم/ملغي)، الاستلام يزيد المخزون ويحدّث **متوسط التكلفة المرجّح** |
| **العملاء** | بحث بالجوال، إضافة سريعة من شاشة البيع، الرقم الضريبي للشركات، سجل المشتريات |
| **التقارير** | المبيعات، المرتجعات، الصافي، ضريبة المخرجات، تكلفة البضاعة، مجمل الربح والهامش، حسب اليوم/طريقة الدفع/الكاشير/المنتج/التصنيف/المقاس، تصدير CSV لـ Excel |
| **لوحة التحكم** | مبيعات وأرباح اليوم والشهر، الرسم اليومي، الأكثر مبيعاً، تنبيهات المخزون، آخر الفواتير |
| **الورديات** | فتح برصيد افتتاحي، ربط كل بيع/مرتجع بالوردية، إيداع/سحب نقدي بسبب، إغلاق بعدّ أعمى، مطابقة الدرج والعجز/الزيادة، تقرير Z مطبوع |
| **الصلاحيات** | المالك / المدير / الكاشير — مطبّقة في قاعدة البيانات (RLS) وليس في الواجهة فقط |
| **سجل التدقيق** | كل إضافة/تعديل/حذف على الجداول الحساسة مع المستخدم والوقت والقيم قبل وبعد |

## التشغيل

- **النشر على Production (Supabase + Vercel):** اتبع [`DEPLOYMENT.md`](DEPLOYMENT.md).
- **التطوير المحلي:**

```bash
cp .env.example .env.local   # رابط مشروع Supabase والمفاتيح
npm install
npm run dev                  # http://localhost:3000
```

### الأوامر

```bash
npm run verify     # قبل كل نشر: typecheck + lint + تحقق حزمة الـ migrations + build + فحص الأسرار
npm run test:db    # اختبارات قاعدة البيانات على PostgreSQL مؤقت (TEST_DATABASE_URL) — يرفض Supabase
npm run db:bundle  # بعد تعديل أي migration: يعيد توليد supabase/setup/01_all_migrations.sql
```

### قرارات تصميم مهمة

- **كل العمليات المالية والمخزنية ذرّية في PostgreSQL** (دوال `security definer` تتحقق من الدور): السعر يُقرأ من قاعدة البيانات، الضريبة تُحسب على الخادم، والمخزون يُخصم في نفس المعاملة — لا يمكن التلاعب بالسعر من المتصفح.
- **المخزون لا يتغير مباشرة**: trigger يمنع تعديل `stock_qty` خارج دوال النظام، وكل تغيير يُسجل في `stock_movements` مع الرصيد بعد الحركة.
- **التكلفة معزولة**: تكلفة الأصناف في جدول `variant_costs` (للمدير فقط)، وعمود `unit_cost` في بنود الفواتير محجوب عن المستخدمين بصلاحيات الأعمدة، والتقارير عبر دوال محمية.
- **توزيع خصم الفاتورة** على السطور نسبياً، وضريبة كل سطر محسوبة ومحفوظة، والمرتجع الأخير لكل سطر يُرجع المتبقي بالضبط لتفادي فروقات التقريب.
- **التوقيت** بتوقيت الرياض في كل التقارير وأرقام الفواتير.

## ملاحظات

- رمز QR يطابق **المرحلة الأولى** من الفوترة الإلكترونية (TLV: البائع، الرقم الضريبي، الوقت، الإجمالي، الضريبة). الربط مع منصة **فاتورة** (المرحلة الثانية — التوقيع والإرسال) يحتاج تكاملاً إضافياً مع ZATCA.
- الطباعة تتم عبر نافذة طباعة المتصفح — اضبط الطابعة الحرارية على هوامش صفر وعرض الورق المناسب.
- الفواتير المعلّقة تُحفظ على الجهاز نفسه.
